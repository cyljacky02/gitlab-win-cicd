### 現場提示詞

先把 `<已彩排的名稱>` 換成實際值，不讓觀眾看到未替換 placeholder：

> 幫我執行 Web 自動化測試情境「<已彩排的名稱>」。完成後列出總數、成功數、失敗數，以及失敗步驟編號與狀態。只根據實際回傳結果；資訊不足請明說，不猜根因。

| 畫面／動作 | 講者要指出什麼 |
|---|---|
| 出現 `run_web_automation_test(scenario=...)` | AI 是提出工具請求；情境由 Server 設定，不是任意 command／BAT 路徑。 |
| 停在人審 | 核對工具名、情境與副作用範圍；尚未核准前不該執行。 |
| 人工核准 | 這是允許**這次**工具請求，不是永久放行所有測試。 |
| 真正執行並回傳 | 區分程序成功、測試成功；沒有新報表、timeout 或 exit code 失敗均如實回報。 |
| AI 整理結果 | 成功／失敗 counts 與 failure step/status 要對得上工具結果。 |

**不能承諾的事：** 最終送給 AI 的 failure 資訊主要只有 `step_number` 與 `status`，沒有完整錯誤描述、expected／actual、locator 或截圖。若追問「優先排查方向」，請先說現有資料不足，再由人提供允許外送的去識別化證據；不能把通用猜測包裝成已確認根因。

可用轉場：

> 我們不是因為 AI 說成功就相信，而是看工具實際回報。接著看寫程式時，人怎麼保留最後的決定權。

## 4. Demo B：先提案，看 Diff，再決定（約 5 分鐘）

### 會前備一個最小 workspace

在自己的可丟棄測試專案中準備 `demo.json`，不要放在正式專案；示例內容：

```json
{
  "message": "Hello"
}
```

若採用其他內容，提示詞、Diff 與預期結果同步修改。先確定檔案已儲存、沒有背景程式改它。

### 現場提示詞

> 請先讀取目前授權專案的 demo.json，僅把 message 的值從 Hello 改成 Hello from AI × MCP。只提出一個 replace_block 修改提案；先不要套用，讓我在 Diff 確認。不要變動其他檔案。

| 步驟 | 操作／觀察 | 講者說法 |
|---|---|---|
| 1 授權 | 在擴充啟用共同開發模式，確認 Root 與有效 grant。 | 「授權的是這個專案，不是整台電腦。」 |
| 2 讀檔 | 看 `dev.read_file` 真正結果。 | 「它讀真實內容，再提案；不是只給一段讓人自己貼的程式。」 |
| 3 提案 | 等候候選檔與 Diff；對照原檔仍是 `Hello`。 | 「候選檔放在擴充儲存區，原檔還沒改。」 |
| 4 檢查／Diff | 看差異、目標路徑與候選語法狀態。 | 「JSON 語法通過，不代表專案功能測試通過。」 |
| 5 駁回（彩排通順才做） | 先駁回一次，確認原檔未變；再用新請求重新提案。 | 「不接受就不套用，人可以說不。」 |
| 6 核准 | 對既有檔按側欄**核准並套用**。該按鈕本身就是人工核准，不另等第二個 modal。 | 「檢查差異後，我才決定把這次修改寫回。」 |
| 7 確認結果 | 讀回檔案／看 Git diff。 | 「現在只能說已套用。沒有跑過的 unit／功能測試，仍是尚未執行。」 |

不要展示「我把所有提示都按確認」；要讓觀眾看見確認的對象與差異。Diff 可供檢視，但系統不能證明人真的閱讀完，Review 責任仍在人。

### 額外負例（有餘裕／Q&A 再做，不塞進 8 分鐘主秀）

在 pending review 時手動修改原檔並存檔，再按套用；應看到版本／hash conflict，舊提案不套用。接著重新讀檔、重新提案，不關閉版本檢查來救場。

這是 stale-version 防護，不是跨程序檔案鎖或絕對 race-free 保證。

## 5. 失敗時的備案與停損

| 狀況 | 應對 |
|---|---|
| Web 登出、DOM／協議讀取失敗 | 停止重送；切換**會前已錄製、已標明版本與錄製日期**的影片。沒有錄影就用第 3 頁邏輯圖走讀。 |
| BAT／測試網站／報表不可用 | 不捏造 counts，不拿舊報表當本次；若列情境可用，改示範唯讀入口與人審路線。 |
| grant 過期或 workspace 不符 | 重新確認專案與授權，不擴大成整個磁碟／不繞過檢查。 |
| Diff、候選語法或 hash conflict | 展示拒絕狀態與重新提案；不要改為直接覆寫檔案。 |
| 工具無回應、執行狀態不明 | 查工作狀態與診斷，先確認舊執行是否仍在進行；不要盲目重試或反覆核准，避免副作用重複。 |
| 沒有任何已驗證的現場環境 | 明說「今天用原始碼與流程圖解說，實機尚待驗證」；6 頁簡報仍可完整分享。 |

**沒有預錄檔案隨本次簡報交付。** 錄影／截圖若由講者另備，須清掉 token、內部主機、客戶資料與原始碼機密，並標為「預錄」；不能冒充現場執行。

## 6. 五句問答備用

- **能取代 Codex 嗎？** 這是補充既有 Web Chat 的執行入口；不保證模型品質、上下文、IDE 體驗或使用額度與 Codex 等同。
- **是不是資料都留在本機？** 不是。工具在地端執行，但結果／原始碼會回到 Web AI，仍需資料使用政策允許。
- **所有寫入都要逐次按核准嗎？** 不是。正式程式碼提案需人審；有效開發流程中的受限 BugList 寫入有自動授權例外。敏感查詢、密碼重設、Web 測試另有逐次核准政策。
- **有 log 就可以上正式嗎？** 不行。現有診斷不是永久、防竄改的企業稽核；身分、網路、憑證、資料與資安驗證仍要補齊。
- **接一個新工具就自然安全嗎？** 不會。要定義輸入、可碰範圍、輸出外送、核准與副作用；scenario 白名單不會把 BAT 自動變成沙箱。

## 7. 講者用的啟動參考（不放投影片、不含秘密）

```powershell

```
